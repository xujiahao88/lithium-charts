### 横轴口径（两套，注意区别）

- `lc_inv`：MM-DD 季节性轴，日期即源表日期（Mysteel 周三口径，单年起步 → 单条红线）。
- `lc_output` / `lc_cathode` / `lc_cell`：源表 A 列是**下载日**，间隔在 5/6/7/8/14 天间漂移，
  跨年还会左右挪 1~2 天。若直接取 (月,日) 建槽位，4 年叠线会横向错开、轴膨胀到 160+ 槽位
  （碳酸锂产量实测 164 期 → 164 槽）。因此统一按 **ISO 周号** 映射到**基准年（最新年）同周的周四**：
  轴收敛为 52 槽，年份间可比。真实日期仍用于 asOf 与「较年初」。
- `lc_order`：同用 ISO 周号锚定。**但源表 2025 年日期标签比 2026 年早 7 天**
  （2026 用「周结束日」，2025 用「周结束日 −7」），脚本对 2025 年日期 +7 天后才取周号，
  否则 2025 线整体左移一周、同比对标失真。校正后 7 品牌合计同比 −41.3%，
  与高盛标题「-41% yoy」吻合即校验通过。
- `lc_order` 的**月度组用第二根轴**（`'1'..'12'`），由 `ds.axisTypes = ['week', 'month']` 指定；
  `app.js` 的 `buildOption` 会读 `ds.axisTypes[chart.axis]` 覆盖原来按 `dsId` 的全局轴判定。
  **以后再加混合轴数据集，必须同时给 `axes` 和 `axisTypes`**，否则月度会被当成 MM-DD 轴、
  标签全不显示（`/-01$/` 匹配不上）。
- 月度横轴固定 `'1'..'12'`，不随年份偏移；2025 线从 3 月起（源表 2 月中旬才有数据，2 月覆盖不足 80% 已剔除）。

- **中联金三表**（`lc_ore_ship` / `lc_chile_ship` / `lc_ore_inv`）也走 ISO 周锚定：
  `d.isocalendar()` → `date.fromisocalendar(2026, w, 4)`，轴为基准年同周周四的 MM-DD。
  但**年份归属与 MA 分组都用 ISO 年 / 日历年**，原因不同：
  - 年份归属用 **ISO 年**：`2026-12-29` 属 2026-W01（ISO 年 2027 前的最后一周），
    若按日历年归年会把它塞进 2026 线末端，导致年底撞槽。
  - MA 分组用**日历年**：2025-W52 与 2026-W01 之间隔了整整一年，
    若连续滚动会把「去年末」和「今年初」平均在一起，MA 失真。

### 分张出图（周度 / 月度分开）

同一数据集混排两根轴时，出图靠两个 URL 参数裁剪，不必复制数据集：

| 参数 | 作用 |
|---|---|
| `?axis=N` | 只渲染 `chart.axis === N` 的图。`lc_order`：0=周度（9 图）、1=月度（9 图） |
| `?nosum=1` | 不渲染顶部汇总表（汇总表是**周度**口径，放进月度图会误导） |

- 对应用法：`shot_lithium.py --axis 1 --no-sum`
- `run_lc_pipeline.py --order` 的 `ORDER_SEGS` 已配好两条，**出两张并逐张发微信**
- 网页正常浏览（不带参数）仍是单 tab 内 18 图 + 汇总表，两张长图只是出图视角
